# Deploy Kadoku on Render (free preview)

This guide deploys an **evaluation environment**, not a real store.
All catalog products are illustrative, all checkouts remain PayPal **Sandbox**,
and no actual fulfillment occurs. Free Render Postgres expires after 30 days
and provides no backups; do not collect real customer data here.

## Deployment layout

The root `render.yaml` creates three resources in **Singapore**:

| Render resource | Runtime | Free preview |
| --- | --- | --- |
| `kadoku-web` | Node 22 / Next.js 16 | Public HTTPS URL |
| `kadoku-api` | Python 3.12 / FastAPI | Public HTTPS URL |
| `kadoku-db` | PostgreSQL | Internal database URL, 30-day expiry |

Both services use the same database: Better Auth owns auth tables; Alembic
owns Kadoku application tables. Secrets are generated by Render and never
committed to Git. The web's guest-cookie signing key references the API's
guest-quota key, ensuring the signatures match.

**Free service networking:** Render free web services cannot accept inbound
traffic from the private network. Consequently, `API_PROXY_TARGET` references
the API's **public HTTPS URL** (via `RENDER_EXTERNAL_URL`), not its internal
hostname. The database still uses its **private** connection string. If you
later upgrade the API to a paid service, private networking can be used.

## Create services

1. Merge the Render blueprint pull request to `main`.
2. Open [Render Dashboard](https://dashboard.render.com/), sign in, then choose
   **New → Blueprint**. Connect the GitHub repository `omkz/kadoku` and
   select the `main` branch / root `render.yaml`.
3. Review the **three Free** resources and confirm Blueprint creation. If your
   workspace already has its one permitted Free Postgres database, choose a
   different plan or an existing compatible database instead of creating a
   second Free database.
4. Observe deploy logs. FastAPI's `startCommand` applies Alembic migrations
   and idempotently seeds the **100 demo catalog items** before serving HTTP.
   Next.js runs the **Better Auth v1.7.18** schema migration in its
   `initialDeployHook` (once after its first successful deploy). Do not
   run the development-only `app.seed_scenarios` command on Render.
5. Wait for the first migrations to complete; test the actual URLs shown in
   your Render dashboard. Service names are not guaranteed to equal exact URL
   hostnames, so never guess the hostname.

No additional API proxy URL, database password, auth URL, or guest-cookie
secret needs to be typed: `render.yaml` links those variables between
Render services. If the Better Auth initial hook fails, inspect the deploy
logs and resolve it before testing sign-in.

### Smoke test

- Open the generated **kadoku-web** HTTPS URL; confirm the homepage loads.
- Open the generated **kadoku-api** URL plus `/api/health`; expect
  `{"status":"ok","service":"kadoku-api"}`.
- Check `https://<actual-web-host>/backend/api/v1/products` responds with
  the demo product list. This confirms the Next.js proxy and API networking.
- Register a **test** account and verify My People/Upcoming moments.
- Check that unauthenticated private/admin endpoints reject access.
- Confirm payments remain blocked until Sandbox credentials are configured.

### Optional: Enable admin

Admin endpoints deny all users by default. Sign up for a **test** Better
Auth account first, retrieve its ID from the auth database (JWT `sub`,
not an email address), then set `ADMIN_USER_IDS` in the **kadoku-api**
service's Render Environment settings. Redeploy API. Never use another user's
ID or make admin access public.

### Optional: PayPal Sandbox

Use **kadoku-api → Environment** to set:

- `PAYPAL_CLIENT_ID`: your Sandbox app's client ID
- `PAYPAL_CLIENT_SECRET`: your Sandbox app's secret
- `PAYPAL_WEBHOOK_ID`: your Sandbox webhook ID (for verification)

The webhook URL is `https://<actual-api-host>/api/v1/webhooks/paypal`.
Keep `PAYPAL_MODE=sandbox`; live checkout is intentionally disabled.
These credentials are **not** needed to load the homepage.

### Optional: AI features

The initial free preview runs the rules-based gift recommender and leaves
`STUDIO_AGENT_ENABLED=false` to avoid unintentional provider costs. To enable
Gemini, change API's build command to `uv sync --frozen --extra ai`,
set `STUDIO_AGENT_ENABLED=true`, `STUDIO_AGENT_MODEL` to an allowed model,
set `GEMINI_API_KEY` as a secret in **API Environment**, and redeploy. The
free 512 MB instance may be insufficient for the extra runtime dependencies;
upgrade compute if memory errors occur. Do not put an AI key in `NEXT_PUBLIC_*`.

## Important Render Free constraints

- **Postgres Free expires after 30 days**, has 1 GB storage and **no backups**.
  After expiry there is a 14-day upgrade grace period; the data is then
  deleted unless the database is upgraded. Do not treat it as production.
- Both free web services **sleep after 15 minutes of inactivity** and can
  need roughly a minute to wake, which may delay auth or initial requests.
- Free web services have no interactive shell or one-off jobs. For this
  reason the FastAPI startup command performs idempotent migrations and
  catalog seeding. Better Auth uses the one-time initial deploy hook.
- Only the catalog is seeded automatically. **Synthetic demo orders are
  deliberately not seeded**, since they would make paid-order analytics
  look like real Sandbox captures.
- Hosted Render service creation, credential entry, and DNS customisation
  must be performed in Render Dashboard. This repository's blueprint alone
  does not create live services until you apply it.
